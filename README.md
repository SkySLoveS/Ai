Архитектура

Решение реализовано на Python. На вход система получает транскрипт разговора и передаёт его вместе с инструкцией в LLM через OpenRouter API. Модель извлекает информацию в заранее определённую JSON-структуру из 7 полей: результат разговора, следующие шаги, дата, потребности, риски, ошибки менеджера и важная информация. После получения ответа Python проверяет корректность JSON и наличие необходимых полей.

Что было проверено

Решение протестировано на нескольких транскриптах с разными сценариями переговоров: отсутствие финального решения, назначение следующих шагов и сроков, определение потребностей клиента, выявление рисков и фиксация ошибок менеджера. Отдельно проверялось, не добавляет ли модель информацию, которой не было в исходном разговоре.

Где решение ошибается

Модель иногда делает логические выводы, которые прямо не указаны в транскрипте. Например, может усилить формулировку клиента («желательно» превратить в «обязательно»), перепутать исполнителя следующего действия или отнести предложение менеджера к потребностям клиента. Поэтому результат модели дополнительно проверяется программно.

Следующая итерация

В следующей версии я бы добавил структурированный выход для более строгого формирования JSON, расширенную валидацию результата и отдельный набор эталонных транскриптов для количественной оценки качества. Также можно добавить дополнительную проверку утверждений модели на соответствие исходному транскрипту.
